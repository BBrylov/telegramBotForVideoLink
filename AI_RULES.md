# Правила для AI-агентов в проекте YouTube Video Downloader Bot

## 1. Цель проекта
Разработка и поддержка Telegram-бота для скачивания видео с YouTube с автоматическим именованием файлов и логированием операций.

## 2. Структура проекта
```
├── bot.py             - Основная логика бота (можно редактировать)
├── config.py          - Загрузка конфигурации (можно редактировать)
├── downloader.py      - Загрузчик видео (можно редактировать)
├── settings.json      - Конфигурация (НЕ РЕДАКТИРОВАТЬ напрямую)
├── requirements.txt   - Зависимости (редактировать через добавление пакетов)
├── .gitignore         - Игнорируемые файлы (можно дополнять)
├── AI_RULES.md        - Этот файл (можно дополнять)
├── logs/              - Логи (только для чтения)
└── downloads/         - Загруженные видео (только для чтения)
```

## 3. Основные правила
### 3.1 Работа с файлами
- Все изменения в коде должны сопровождаться комментариями
- Запрещено изменять `settings.json` напрямую - используйте отдельный конфиг
- При добавлении новых зависимостей обновляйте `requirements.txt`

### 3.2 Обработка данных
- Видеофайлы должны сохраняться в формате: `<channel>_YYYY-MM-DD_<title>.mp4`
- Все пользовательские данные должны обрабатываться анонимно
- Логи должны содержать только техническую информацию (без персональных данных)

### 3.3 Безопасность
- Никогда не коммитить токены или секретные ключи
- Все внешние запросы должны иметь обработку исключений
- Использовать лимиты запросов к YouTube API

## 4. Процедуры разработки
1. Все изменения должны проходить через отдельные git-ветки
2. Перед коммитом:
   - Проверить соответствие PEP8
   - Убедиться в работоспособности через тесты
   - Обновить документацию при необходимости
3. Для добавления новых функций создавать отдельные модули

## 5. Особенности работы с ботом
- Все операции с пользователем должны быть асинхронными
- Максимальное время обработки запроса - 5 минут
- При ошибках скачивания отправлять понятное сообщение пользователю
- Логировать все критические операции в `logs/bot.log`

## 6. Рекомендации
- Использовать type hints для всех функций
- Документировать публичные методы через docstrings
- Сохранять обратную совместимость при изменениях API
